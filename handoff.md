### Bugs found and fixed in session 2 (reported to the user)
- `crt` / `tcrt`: wrong answer whenever `gcd(n1, n2) > 1` (missing `/ gcd`); the asserts that would catch it are off under NDEBUG.
- `divsum_sieve` / `mobius_sieve`: `isPrime` was only set for primes <= sqrt(N).
- `ncr_linear` (exact): overflowed for large r (`ncr_linear(21, 19)` = 58); now uses symmetry and divides as it goes.
- `point::dot` returned `a.x*b.x + a.y + b.y`.
- `bigint`: `operator=(long long)` appended instead of replacing; `gcd` of negatives was negative.
- `trie_string`: same three bugs as the old `trie` (destructor, `count("", prefix)`, `maxPrefixWord` after erase).
- `rabin_karp` did not compile against `string_hashing` (`T.hash`, `pair<int,int>` from mints).
- `manacher`: read `p[-1]` (harmless value, but UB; found by `_GLIBCXX_ASSERTIONS`).
- `binary_tree`: `node(int data) : val(val)` (uninitialised value).
- Metadata: `dag_cycle` had `@needs topological_sort_bfs` but carries its own copy (redefinition); `kruskal` lacked `@needs dsu`.
- `centroid_tree`: `centroid_parent(n)` started at 0 instead of -1, so `query` looped forever.
- `bexp`: an unreduced base overflowed in `a * a`; now `a %= mod` first.
- `count_bits_0_to_N(0)`: indexed `pow2[-1]` / `ones[N]`; returns all zeros now.
- `Pow`: the final, unused `a *= a` could overflow (signed-overflow UB) even when the answer fits.
- `generate_all_ceils`: returned floor values that are not ceils (l = 9 gave 4); one filter line added.
- `calculate_mex`: negative values indexed out of bounds (same bug as `mex` in session 1).
- `dp/lis` (`LIS(a, n)`): returned 1 for an empty array.
- `generate_all_ceils` used `sz`, which the boilerplate does not define; `mod_div` lacked `@needs mod_mul`.
- Cosmetic warning fixes: sign-compare casts, `hilbert_order` parentheses, `centroid_tree` init order, `inline` hash moduli.

### 7. Known limitations
- Recursive snippets (LCA, binary lifting, HLD, segment trees) need judge-sized stacks; on a local Windows run with
  the default 1 MB stack, a 2e5-deep path tree overflows. Tests link with 256 MB (`-Wl,--stack,268435456`).
- `line_container` keeps the original's global query flag (renamed `line_container_q`).
- `treap` / `trie` / `dynamic` use `new` like the originals (treap nodes are owned by the caller).
- No ASan/TSan on this MinGW. For a real race/memory check of `low_level/`, run the suite in WSL Ubuntu
  (`-DENABLE_ASAN=ON` / `-DENABLE_TSAN=ON`).

**How each language includes the exact snippet text** (like `#include "lib/..."` in the C++ tests):
- Java has no `#include`. A snippet is a *member* of `Main` (a `static class seg_tree`, `static long` methods), so
  `tools/java_test.py` wraps each file as `final class Snip_seg_tree { <file text> }` under `build/java/src/` and the
  test uses `Snip_seg_tree.seg_tree`. Statement-level snippets (dijkstra, bridges) are wrapped in a static method,
  like the C++ tests do with functions.
- Rust: `mod imp { include!("seg_tree.rs"); }` in `lib/.../seg_tree/test_seg_tree.rs` (path relative to the test file).
  `include!` pastes the file as is, so tests compile the same text the plugin inserts.

**Conventions to carry over:**
- Values are `long` / `i64` (the C++ `#define int long long` equivalent). Java: specialize on `long[]` with a
  `LongBinaryOperator` merge instead of `T` generics (boxing is too slow for contests); Rust: generic `T: Copy` plus
  a closure type parameter `F: Fn(T, T) -> T`, the analogue of the deduced C++ lambda.
- Inclusive `[l, r]` everywhere it is inclusive in C++; `fenwick.sum(a, b)` stays half-open.
- Recursion is kept: Rust tests set `RUST_MIN_STACK = "268435456"` in `tests/rust/.cargo/config.toml`; Java tests run
  in a `new Thread(null, r, "", 1 << 28)` like contest solutions do, so both match the 256 MB judge stack.
- Same metadata comments (`// @trigger`, `// @aliases`, `// @needs`, `// @fragment`, `// $0`): `//` is a comment in both.

**Tests**: same as C++: a randomized differential test against a brute-force model (same seeds/sizes as
`tests/test_util.hpp`, ported to a small `TestUtil` / `test_util.rs`) plus an edge-case test per structure.

**Plugin**: `cp_snippets.py` indexes `.java` / `.rs` files in the same `lib/` tree and picks the extension by scope (`source.c++`,
`source.java`, `source.rust`); `cp_insert_snippet` lists the current file's language.
